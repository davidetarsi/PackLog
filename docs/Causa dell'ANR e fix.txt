Causa dell'ANR
Il main thread era bloccato >5 secondi prima di runApp() perché tutte le inizializzazioni pesanti avvenivano in sequenza:

EasyLocalization.ensureInitialized()
await Future.wait([Supabase.initialize, Amplitude.init, _initializePersistence]) — lento (network + DB migration + backup)
SentryFlutter.init(appRunner: () => runApp(app)) — lento (native SDK, file I/O)
Android triggera ANR dopo ~5 sec senza primo frame.

Fix applicata
SentryWidgetsFlutterBinding.ensureInitialized() al posto di WidgetsFlutterBinding — risolve anche il warning FramesTrackingIntegration disabled nel log

Deferred bootstrap via appBootstrapProvider — Supabase, Amplitude e persistenza vengono inizializzati dopo runApp() tramite un FutureProvider, non più nel bootstrap()

Splash screen durante il loading — MyApp ora osserva appBootstrapProvider con AsyncValue.when():

loading → MaterialApp con CircularProgressIndicator
error → schermata di errore
data → MaterialApp.router con il router completo (Supabase è pronto, auth funziona)
Timeline prima vs dopo
Prima: binding → EasyLoc → Supabase+Amplitude+DB → Sentry → runApp() = ~3-7 sec bloccati
Dopo: binding → EasyLoc → Sentry → runApp() = ~1-2 sec, poi splash screen mentre il resto si inizializza in background
