Cloud Services Implementation GuideQuesto documento descrive come sono stati implementati Supabase, Amplitude e Sentry nel progetto Pack Log, dove si trovano nel codice, e gli step necessari per collegare l'app ai rispettivi servizi cloud.---IndiceArchitettura GeneraleSupabaseAmplitudeSentrySetup Step-by-StepVariabili d'AmbienteComandi di Build---Architettura GeneraleTutti e tre i servizi seguono lo stesso pattern architetturale:```dart-define (compile-time)    │    ▼AppConfig (lib/shared/config/app_config.dart)    │    ▼bootstrap.dart (inizializzazione sequenziale)    │    ├──► Supabase.initialize()    ├──► Amplitude.getInstance().init()    └──► SentryFlutter.init()         │         └──► runApp() (dentro Sentry per catturare crash globali)```Le API key vengono iniettate a compile-time via `--dart-define` (nessun file `.env` nel repo). La validazione avviene in `AppConfig.validate()`:Produzione: chiavi mancanti bloccano l'avvio (throw `StateError`)Sviluppo: chiavi mancanti generano un warning ma l'app si avvia comunque---SupabaseScopoBackend-as-a-Service per autenticazione (Google OAuth + Email/Password) e database remoto (sincronizzazione offline-first con LWW conflict resolution).File CoinvoltiFile	Responsabilita`lib/shared/config/app_config.dart`	`SUPABASE_URL` e `SUPABASE_ANON_KEY``lib/bootstrap.dart`	`Supabase.initialize(url, anonKey)``lib/core/auth/auth_repository.dart`	Interfaccia astratta auth`lib/core/auth/supabase_auth_repository.dart`	Implementazione auth con Supabase`lib/core/auth/auth_provider.dart`	Riverpod provider + identity resolution`lib/core/auth/auth_state.dart`	Sealed class: Authenticated / Unauthenticated`lib/core/auth/auth_exceptions.dart`	Eccezioni tipizzate (SignIn/SignUp/SignOut)`lib/core/sync/supabase_repository.dart`	Repository CRUD remoto (fetch/upsert)`lib/core/sync/sync_service.dart`	Logica LWW + serializzazione Drift ↔ JSON`lib/core/sync/sync_orchestrator.dart`	Trigger automatico su connectivity/resume`lib/core/sync/sync_provider.dart`	Riverpod wiring dei servizi sync`lib/core/database/tables/mixins/syncable_table.dart`	Colonne sync nel DB localeInizializzazione```dart// bootstrap.dart (riga 101-104)await Supabase.initialize(  url: AppConfig.supabaseUrl,  anonKey: AppConfig.supabaseAnonKey,);```AutenticazioneL'autenticazione e gestita da `SupabaseAuthRepository` che implementa l'interfaccia `AuthRepository`:```dart// Metodi disponibili:signInWithGoogle()    // OAuth via Google Sign-In nativosignInWithEmail()    // Email + passwordsignUpWithEmail()    // Registrazione emailsignOut()            // Logout (Google + Supabase)```Flusso OAuth Google:`GoogleSignIn().signIn()` ottiene `idToken` + `accessToken``supabaseClient.auth.signInWithIdToken(provider: google, idToken, accessToken)`Supabase crea/recupera l'utente e restituisce una sessione JWTGestione stato auth (Riverpod):`authNotifierProvider` ascolta `supabase.auth.onAuthStateChange`Su ogni cambio stato, `_resolveIdentity()` identifica l'utente in Sentry e Amplitude`currentUserIdProvider` espone l'userId nullable per il resto dell'appSincronizzazione Offline-FirstSchema DB locale (SyncableTable mixin):```dartuserId              // ID utente Supabase (nullable per record pre-login)syncStatus          // synced | pendingCreate | pendingUpdate | pendingDeletesyncRetryCount      // Contatore tentativi fallitilastSyncError       // Ultimo messaggio di erroresentryTraceId       // Correlazione con SentrynextSyncAttemptAt   // Backoff esponenziale (2^n secondi)```Flusso di sync (SyncService._syncRecord):```1. Fetch remoto (fetchTripById)2. Se remote == null → PUSH locale (upsert)3. Se localUpdatedAt > remoteUpdatedAt → PUSH locale (LWW: local vince)4. Altrimenti → PULL remoto (LWW: remote vince, sovrascrive locale)5. markSynced() → syncStatus = synced, retryCount = 0```Ordine FK-safe: Houses → Items → Trips (rispetta foreign key dependencies)Trigger automatici (SyncOrchestrator):App torna in foreground (`AppLifecycleState.resumed`)Connettivita ripristinata (WiFi/Mobile via `connectivity_plus`)Mutex `_isSyncing` previene sync concorrentiSupabaseRepository - Metodi Esposti```dartfetchHouseById(id, {sentryTrace?}) → Map<String, dynamic>?upsertHouse(data, {sentryTrace?}) → voidfetchItemById(id, {sentryTrace?}) → Map<String, dynamic>?upsertItem(data, {sentryTrace?}) → voidfetchTripById(id, {sentryTrace?}) → Map<String, dynamic>?upsertTrip(data, {sentryTrace?}) → void```Ogni metodo inietta l'header `sentry-trace` nella REST call per distributed tracing.---AmplitudeScopoProduct analytics per tracciare eventi chiave dell'utente (creazione casa, aggiunta item, creazione viaggio) e comprendere l'adozione delle feature.File CoinvoltiFile	Responsabilita`lib/shared/config/app_config.dart`	`AMPLITUDE_API_KEY``lib/bootstrap.dart`	`Amplitude.getInstance().init(apiKey)``lib/core/analytics/analytics_service.dart`	Wrapper low-level Amplitude`lib/core/analytics/core_analytics_service.dart`	Eventi di dominio (House, Item, Trip)`lib/core/auth/auth_provider.dart`	User identification su login/logoutInizializzazione```dart// bootstrap.dart (riga 106)await Amplitude.getInstance().init(AppConfig.amplitudeApiKey);```Struttura a Due LivelliLivello 1 - AppAnalyticsService (wrapper generico):```dartclass AppAnalyticsService {  void identifyUser(String userId);     // Associa eventi all'utente  void clearUser();                      // Anonimizza su logout  Future<void> logEvent(String name, {Map<String, dynamic>? properties});}```Livello 2 - CoreAnalyticsService (eventi di dominio):```dartclass CoreAnalyticsService {  Future<void> trackHouseCreated({houseId, totalHouses});  Future<void> trackItemAdded({itemId, category, totalItems});  Future<void> trackTripCreated({tripId, totalTrips});}```Eventi TracciatiEvento	Properties	Quando`House_Created`	`house_id`, `is_first_house`	Utente crea una nuova casa`Item_Added`	`item_id`, `item_category`, `is_first_item`	Utente aggiunge un oggetto`Trip_Created`	`trip_id`, `is_first_trip`	Utente crea un nuovo viaggioIdentificazione Utente```dart// auth_provider.dart - _resolveIdentity()case Authenticated(:final userId):  ref.read(analyticsServiceProvider).identifyUser(userId);case Unauthenticated():  ref.read(analyticsServiceProvider).clearUser();```GDPR-compliant: solo `userId` (UUID Supabase), nessuna email o PII.Gestione ErroriTutti i metodi di Amplitude sono wrappati in try-catch con `debugPrint`. Un errore di analytics non deve mai crashare l'app.---SentryScopoError monitoring + performance monitoring per catturare crash, errori di sync, e tracciare le performance delle operazioni critiche.File CoinvoltiFile	Responsabilita`lib/shared/config/app_config.dart`	`SENTRY_DSN``lib/bootstrap.dart`	`SentryFlutter.init()` con environment e sample rate`lib/core/monitoring/monitoring_service.dart`	AppMonitoringService (breadcrumbs, user ID, trace ID)`lib/core/sync/sync_service.dart`	Transactions, captureException, breadcrumbs`lib/core/sync/supabase_repository.dart`	Iniezione header `sentry-trace` in REST calls`lib/core/auth/auth_provider.dart`	User identification su login/logout`lib/core/database/tables/mixins/syncable_table.dart`	Colonna `sentryTraceId` nel DBInizializzazione```dart// bootstrap.dart (riga 113-132)await SentryFlutter.init(  (options) {    options.dsn = AppConfig.sentryDsn;    options.environment = env.name;  // 'dev' o 'prod'    options.tracesSampleRate = env == Environment.prod ? 0.2 : 1.0;  },  appRunner: () => runApp(...),  // L'app gira DENTRO Sentry);```Nota: `runApp()` e dentro `appRunner` di Sentry, il che garantisce che qualsiasi eccezione non gestita nel framework Flutter venga automaticamente catturata.AppMonitoringService```dartclass AppMonitoringService {  void identifyUser(String userId);        // Sentry.configureScope → setUser  void clearUser();                         // Sentry.configureScope → setUser(null)  void logBreadcrumb(message, {category, data});  // Sentry.addBreadcrumb  String generateTraceId();                 // UUID v4 per correlazione}```Dove Vengono Loggati gli Eventi1. Breadcrumbs (traccia di navigazione prima di un crash)Posizione	Messaggio	Dati`sync_service.dart:39`	"Avvio batch sync: N case, N item, N viaggi"	`houses_count`, `items_count`, `trips_count``sync_orchestrator.dart:57`	"Avvio sincronizzazione automatica. Trigger: X"	`trigger` (connectivity_restored / app_resume)2. Exception Capture (errori critici)Posizione	Contesto`sync_service.dart:145`	`Sentry.captureException(e, stackTrace: st)` quando un record fallisce la sync3. Performance Transactions (tempi di esecuzione)Posizione	Transaction Name	Operation`sync_service.dart:108`	`sync.house`	`sync.process``sync_service.dart:108`	`sync.item`	`sync.process``sync_service.dart:108`	`sync.trip`	`sync.process`Ogni transaction:E legata allo scope corrente (`bindToScope: true`)Porta il `sentryTraceId` come data aggiuntivoGenera un `traceHeader` iniettato nelle chiamate REST a SupabaseTermina con `SpanStatus.ok()` o `SpanStatus.internalError()`4. Distributed Tracing (Supabase ↔ Sentry)```dart// supabase_repository.dart - _withTrace()_client.rest.headers['sentry-trace'] = sentryTrace;```L'header `sentry-trace` viene iniettato in ogni chiamata REST verso Supabase, permettendo di correlare le performance della REST API con le transaction Sentry lato client.5. Identificazione Utente```dart// auth_provider.dart - _resolveIdentity()case Authenticated(:final userId):  ref.read(monitoringServiceProvider).identifyUser(userId);// → Sentry.configureScope((scope) => scope.setUser(SentryUser(id: userId)))```Sample RateEnvironment	`tracesSampleRate`	Significato`dev`	`1.0` (100%)	Tutte le transaction vengono inviate`prod`	`0.2` (20%)	Solo il 20% per non impattare costi/performance---Setup Step-by-Step1. SupabaseCrea un progetto su supabase.comCopia le credenziali da Settings → API:`Project URL` → `SUPABASE_URL``anon public` key → `SUPABASE_ANON_KEY`Crea le tabelle nel SQL Editor (houses, items, spaces, luggages, trips) con le stesse colonne delle tabelle Drift + colonne syncConfigura RLS (Row Level Security):```sql   ALTER TABLE houses ENABLE ROW LEVEL SECURITY;   CREATE POLICY "Users can CRUD their own houses"     ON houses FOR ALL     USING (auth.uid() = user_id)     WITH CHECK (auth.uid() = user_id);   -- Ripetere per items, spaces, luggages, trips   ```Configura Auth Providers:Authentication → Providers → Google → AbilitaInserisci `Web Client ID` e `Web Client Secret` da Google Cloud ConsoleGoogle Cloud Console:Crea un progetto OAuth 2.0Configura OAuth consent screenCrea credenziali OAuth (Web + Android)Il `Web Client ID` va in Supabase, l'`Android Client ID` va nel manifestAndroid setup (`android/app/src/main/AndroidManifest.xml`):Assicurati che il `SHA-1` fingerprint sia registrato in Google Cloud Console2. AmplitudeCrea un progetto su amplitude.comCopia l'API Key da Settings → Projects → [Il tuo progetto] → General`API Key` → `AMPLITUDE_API_KEY`Nessuna altra configurazione necessaria: l'SDK Flutter fa il restoVerifica: dopo il primo login, controlla in Amplitude → User Lookup che l'utente appaia con il suo `userId`3. SentryCrea un progetto Flutter su sentry.ioCopia il DSN da Settings → Projects → [Il tuo progetto] → Client Keys (DSN)`DSN` → `SENTRY_DSN`Upload dei simboli di debug (per deobfuscazione in produzione):```bash   # Dopo la build di produzione   flutter build appbundle --obfuscate --split-debug-info=build/debug-info      # Upload su Sentry   sentry-cli upload-dif --org <org> --project <project> build/debug-info/   ```Configura Source Maps (opzionale per web):Sentry → Settings → Projects → Source MapsVerifica: triggerare un crash manuale in dev e verificare che appaia in Sentry Issues---Variabili d'AmbienteTutte le variabili sono iniettate a compile-time via `--dart-define`:Variabile	Servizio	Dove Trovarla`SUPABASE_URL`	Supabase	Supabase Dashboard → Settings → API → Project URL`SUPABASE_ANON_KEY`	Supabase	Supabase Dashboard → Settings → API → anon public`AMPLITUDE_API_KEY`	Amplitude	Amplitude → Settings → Projects → API Key`SENTRY_DSN`	Sentry	Sentry → Settings → Client Keys (DSN)`GEOAPIFY_KEY`	Geoapify	geoapify.com → My Projects → API KeyValidazione (AppConfig.validate)```dartstatic void validate() {  final missing = <String>[];  if (supabaseUrl == 'MISSING_SUPABASE_URL') missing.add('SUPABASE_URL');  if (supabaseAnonKey == 'MISSING_SUPABASE_ANON_KEY') missing.add('SUPABASE_ANON_KEY');  if (sentryDsn == 'MISSING_SENTRY_DSN') missing.add('SENTRY_DSN');  if (amplitudeApiKey == 'MISSING_AMPLITUDE_API_KEY') missing.add('AMPLITUDE_API_KEY');  if (missing.isNotEmpty) throw StateError('Variabili mancanti: ${missing.join(", ")}');}```---Comandi di BuildSviluppo (con tutte le variabili)```bashflutter run \  --dart-define=SUPABASE_URL=https://xxxxx.supabase.co \  --dart-define=SUPABASE_ANON_KEY=eyJhbGci... \
